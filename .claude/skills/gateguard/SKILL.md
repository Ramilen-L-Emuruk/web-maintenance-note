# GateGuard — ファクト強制プリアクションゲート

Edit 前に Claude に調査を強制する PreToolUse フック。自己評価（「本当にいいですか？」）ではなく、具体的な事実を要求する。調査行為そのものが、自己評価では得られなかった認識を生み出す。

## 起動タイミング

- ファイル編集が複数モジュールに影響するコードベースでの作業
- 特定のスキーマや日付フォーマットを持つデータファイルがあるプロジェクト
- AI 生成コードが既存パターンに一致する必要があるチーム
- Claude が調査せずに推測する傾向がある場合

## コアコンセプト

LLM の自己評価は機能しない。「ポリシーに違反していませんか？」と聞いても、答えは常に「いいえ」になる。これは実験で検証済み。

しかし「このモジュールをインポートしているファイルをすべてリストして」と求めると、LLM は Grep と Read を実行せざるを得ない。調査そのものがコンテキストを生成し、出力を変える。

**3段階ゲート:**

```
1. DENY  — 最初の Edit/Write/Bash 試行をブロック
2. FORCE — 収集すべき事実を具体的に指示
3. ALLOW — 事実が提示された後にリトライを許可
```

3段階すべてを実行する競合はない。ほとんどは deny で止まる。

## エビデンス

2つの独立した A/B テスト、同一エージェント、同じタスク:

| タスク | ゲートあり | ゲートなし | 差分 |
| --- | --- | --- | --- |
| 分析モジュール | 8.0/10 | 6.5/10 | +1.5 |
| Webhook バリデーター | 10.0/10 | 7.0/10 | +3.0 |
| **平均** | **9.0** | **6.75** | **+2.25** |

両エージェントとも動作しテストに通るコードを生成する。違いは設計の深さ。

## ゲート種別

### Edit / MultiEdit ゲート（ファイルごとの初回編集）

MultiEdit も同様に処理 — バッチ内の各ファイルが個別にゲートされる。

```
{file_path} を編集する前に、以下の事実を提示してください:

1. このファイルをインポート/require しているファイルをすべてリスト（Grep 使用）
2. この変更で影響を受ける public 関数/クラスをリスト
3. このファイルがデータファイルを読み書きする場合、フィールド名、構造、
   日付フォーマットを提示（本番データではなく、編集済みまたは合成値を使用）
4. ユーザーの現在の指示をそのまま引用
```

### Write ゲート（初回の新規ファイル作成）

```
{file_path} を作成する前に、以下の事実を提示してください:

1. この新しいファイルを呼び出すファイルと行を特定
2. 同じ目的の既存ファイルがないことを確認（Glob 使用）
3. このファイルがデータファイルを読み書きする場合、フィールド名、構造、
   日付フォーマットを提示（本番データではなく、編集済みまたは合成値を使用）
4. ユーザーの現在の指示をそのまま引用
```

### 破壊的 Bash ゲート（破壊的コマンドのたびに）

トリガー対象: `rm -rf`、`git reset --hard`、`git push --force`、`drop table` 等

```
1. このコマンドが変更または削除するファイル/データをすべてリスト
2. ロールバック手順を1行で記述
3. ユーザーの現在の指示をそのまま引用
```

### 通常 Bash ゲート（セッションにつき1回）

```
ユーザーの現在の指示をそのまま引用してください。
```

## クイックスタート

### オプション A: ECC フックを使用（インストール不要）

`scripts/hooks/gateguard-fact-force.js` のフックがこのプラグインに含まれている。hooks.json で有効化。

### オプション B: 設定付きフルパッケージ

```bash
pip install gateguard-ai
gateguard init
```

プロジェクトごとの設定（カスタムメッセージ、無視パス、ゲートトグル）用の `.gateguard.yml` が追加される。

## アンチパターン

- **自己評価で代替しない。**「本当にいいですか？」は常に「はい」を返す。これは実験で検証済み。
- **データスキーマチェックをスキップしない。** 両 A/B テストエージェントが ISO-8601 日付を想定したが、実データは `%Y/%m/%d %H:%M` だった。データ構造の確認（編集済み値で）がこのバグクラス全体を防止する。
- **すべての Bash コマンドにゲートをかけない。** 通常 Bash はセッションに1回、破壊的 Bash は毎回。このバランスが遅延を避けつつリスクを捕捉する。

## ベストプラクティス

- ゲートを自然に発動させる。ゲートの質問に先回りして答えようとしない — 調査そのものが品質を向上させる。
- ドメインに合わせてゲートメッセージをカスタマイズする。プロジェクト固有の規約がある場合、ゲートプロンプトに追加する。
- `.gateguard.yml` で `.venv/`、`node_modules/`、`.git/` 等のパスを除外する。
