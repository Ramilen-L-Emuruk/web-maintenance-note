# コードレビュー

指定されたファイルまたはモジュール全体に対して、以下の観点でレビューを実施してください。
問題を発見したら、ファイルパス・行番号・修正案を含めて報告してください。

対象が指定されていない場合は、直近の `git diff` の変更ファイルをレビュー対象とします。

---

## 1. フォーマット

- [ ] クラス／インターフェース／enum 宣言の直後に空行がないこと
- [ ] メソッド宣言の直後に空行がないこと
- [ ] メソッド末尾の `return` 直前や閉じ括弧 `}` の前に不要な空行がないこと

## 2. JavaDoc

- [ ] 空の `@param`、`@return`、`@throws` タグに説明が記載されていること
- [ ] クラス JavaDoc が未記載または不十分でないこと（クラスの責務が明確に記述されていること）
- [ ] 誤訳・不正確な記述がないこと（例: 「インストラクタ」→「インスタンス」）

## 3. リファクタリング

- [ ] 定数フィールドに `final` 修飾子が付いていること（`public static` で変更されないフィールド）
- [ ] 具象フィールドを持たない抽象クラスに効果のない `@Getter`/`@Setter` が付いていないこと
- [ ] 不変の計算結果（例: `enum.values()` + `Arrays.sort()`）が `static final` フィールドにキャッシュされていること
- [ ] サイレントな空 catch ブロックにログ出力が追加されていること
- [ ] 冗長な boolean 比較（`== true` / `== false`）が除去されていること
- [ ] コメントアウトされたデッドコードが残っていないこと
- [ ] レガシー API（`Calendar`/`Date`）が `java.time` API に置き換えられていること
- [ ] 未使用の import が除去されていること

## 4. コード規約

- [ ] 既存の定数参照（`CoreConst.XXX` 等）を直値（`"XXX"`）に置き換えていないこと
- [ ] テスト以外でリフレクションを使用してプライベートフィールドを変更していないこと

---

## レビュー手順

1. 対象ファイルを `Read` で読み込む
2. 上記チェックリストの各項目を確認する
3. 問題を発見した場合、以下の形式で報告する：
   - **ファイル**: `path/to/File.java:行番号`
   - **カテゴリ**: フォーマット / JavaDoc / リファクタリング / コード規約
   - **問題**: 具体的な問題の説明
   - **修正案**: 修正後のコード
4. ユーザーの承認後、修正を適用する
