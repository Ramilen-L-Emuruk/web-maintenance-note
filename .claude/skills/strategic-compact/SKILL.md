# 戦略的コンパクトスキル

任意の自動コンパクションに頼らず、ワークフローの戦略的なポイントで手動 `/compact` を提案する。

## 起動タイミング

- コンテキスト制限に近づく長いセッション（200K+ トークン）
- マルチフェーズタスク（調査 → 計画 → 実装 → テスト）
- 同一セッション内で無関係なタスクを切り替える場合
- 主要なマイルストーンを完了し、新しい作業を開始する場合
- レスポンスが遅くなる、または整合性が低下した場合（コンテキスト圧力）

## なぜ戦略的コンパクションか？

自動コンパクションは任意のポイントでトリガーされる:
- しばしばタスク途中で発動し、重要なコンテキストを失う
- 論理的なタスク境界を認識しない
- 複雑なマルチステップ操作を中断する可能性がある

論理的な境界での戦略的コンパクション:
- **探索後、実行前** — 調査コンテキストをコンパクト、実装計画を保持
- **マイルストーン完了後** — 次のフェーズをフレッシュに開始
- **大きなコンテキスト切り替え前** — 別のタスクの前に探索コンテキストをクリア

## 仕組み

`suggest-compact.js` スクリプトは PreToolUse（Edit/Write）で実行され:

1. **ツール呼び出しを追跡** — セッション内のツール呼び出し回数をカウント
2. **閾値検出** — 設定可能な閾値（デフォルト: 50回）で提案
3. **定期的なリマインダー** — 閾値後25回ごとにリマインド

## フック設定

`~/.claude/settings.json` に追加:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "node ~/.claude/skills/strategic-compact/suggest-compact.js" }]
      },
      {
        "matcher": "Write",
        "hooks": [{ "type": "command", "command": "node ~/.claude/skills/strategic-compact/suggest-compact.js" }]
      }
    ]
  }
}
```

## 設定

環境変数:
- `COMPACT_THRESHOLD` — 最初の提案までのツール呼び出し回数（デフォルト: 50）

## コンパクション判断ガイド

このテーブルでコンパクションの判断を行う:

| フェーズ遷移 | コンパクト？ | 理由 |
|-------------|------------|------|
| 調査 → 計画 | はい | 調査コンテキストは大きい; 計画が蒸留された出力 |
| 計画 → 実装 | はい | 計画は TodoWrite またはファイルに保存済み; コード用にコンテキストを解放 |
| 実装 → テスト | 場合による | テストが最近のコードを参照する場合は保持; フォーカスを切り替える場合はコンパクト |
| デバッグ → 次の機能 | はい | デバッグトレースが無関係な作業のコンテキストを汚染する |
| 実装途中 | いいえ | 変数名、ファイルパス、途中の状態を失うコストが高い |
| 失敗したアプローチの後 | はい | 新しいアプローチを試す前に行き止まりの推論をクリア |

## コンパクション後に残るもの

何が持続するかを理解すれば、安心してコンパクトできる:

| 持続する | 失われる |
|---------|---------|
| CLAUDE.md の指示 | 中間的な推論と分析 |
| TodoWrite タスクリスト | 以前に読んだファイル内容 |
| メモリファイル（`~/.claude/memory/`） | マルチステップの会話コンテキスト |
| Git 状態（コミット、ブランチ） | ツール呼び出し履歴とカウント |
| ディスク上のファイル | 口頭で述べられた微妙なユーザー好み |

## ベストプラクティス

1. **計画後にコンパクト** — 計画が TodoWrite で確定したら、フレッシュに開始するためにコンパクト
2. **デバッグ後にコンパクト** — 続行前にエラー解決コンテキストをクリア
3. **実装途中ではコンパクトしない** — 関連する変更のコンテキストを保持
4. **提案を読む** — フックが「いつ」を教え、あなたが「するか」を決定
5. **コンパクト前に書き出す** — コンパクト前に重要なコンテキストをファイルやメモリに保存
6. **`/compact` にサマリーを付ける** — カスタムメッセージを追加: `/compact 次は認証ミドルウェアの実装に集中`

## トークン最適化パターン

### トリガーテーブル遅延読み込み
セッション開始時にスキル全内容をロードする代わりに、キーワードをスキルパスにマッピングするトリガーテーブルを使用。スキルはトリガーされた時のみロードされ、ベースラインコンテキストを50%以上削減:

| トリガー | スキル | ロードタイミング |
|---------|-------|----------------|
| "test", "tdd", "coverage" | tdd-workflow | ユーザーがテストに言及 |
| "security", "auth", "xss" | security-review | セキュリティ関連作業 |
| "deploy", "ci/cd" | deployment-patterns | デプロイメントコンテキスト |

### コンテキスト構成の意識
コンテキストウィンドウの消費を監視:
- **CLAUDE.md ファイル** — 常にロード、簡潔に保つ
- **ロードされたスキル** — 各スキルが 1-5K トークンを追加
- **会話履歴** — やり取りごとに増大
- **ツール結果** — ファイル読み込み、検索結果がボリュームを追加

### 重複指示の検出
重複コンテキストの一般的な原因:
- `~/.claude/rules/` とプロジェクトの `.claude/rules/` の両方に同じルール
- CLAUDE.md の指示を繰り返すスキル
- 重複するドメインをカバーする複数のスキル

### コンテキスト最適化ツール
- `token-optimizer` MCP — コンテンツ重複排除による自動95%以上のトークン削減
- `context-mode` — コンテキスト仮想化（315KB から 5.4KB の実績）

## 関連

- メモリ永続化フック — コンパクションを超えて持続する状態向け
- `continuous-learning` スキル — セッション終了前にパターンを抽出
