# コンテキストバジェット

Claude Code セッションでロードされる全コンポーネントのトークンオーバーヘッドを分析し、コンテキストスペースを回収するための実行可能な最適化を提示する。

## 使用タイミング

- セッションのパフォーマンスが遅く感じる、または出力品質が低下している
- 最近多くのスキル、エージェント、または MCP サーバーを追加した
- 実際にどれだけのコンテキスト余裕があるか知りたい
- さらにコンポーネントを追加する予定で、余裕があるか確認したい

## 仕組み

### フェーズ 1: インベントリ

全コンポーネントディレクトリをスキャンし、トークン消費を推定:

**エージェント** (`agents/*.md`)
- ファイルごとの行数とトークン数をカウント（単語数 × 1.3）
- `description` フロントマターの長さを抽出
- フラグ: 200 行超（重い）、description が 30 ワード超（フロントマター肥大化）

**スキル** (`skills/*/SKILL.md`)
- SKILL.md ごとのトークン数をカウント
- フラグ: 400 行超
- `.agents/skills/` 内の重複コピーを確認 — 二重カウントを避けるため同一コピーをスキップ

**ルール** (`rules/**/*.md`)
- ファイルごとのトークン数をカウント
- フラグ: 100 行超
- 同じ言語モジュール内のルールファイル間のコンテンツ重複を検出

**MCP サーバー** (`.mcp.json` またはアクティブ MCP 設定)
- 設定済みサーバー数と総ツール数をカウント
- ツールあたり約 500 トークンのスキーマオーバーヘッドを推定
- フラグ: 20 ツール超のサーバー、単純な CLI コマンドをラップするサーバー

**CLAUDE.md** (プロジェクト + ユーザーレベル)
- CLAUDE.md チェーン内の各ファイルのトークン数をカウント
- フラグ: 合計 300 行超

### フェーズ 2: 分類

各コンポーネントをバケットに仕分け:

| バケット | 基準 | アクション |
|---------|------|----------|
| **常に必要** | CLAUDE.md で参照、アクティブコマンドをバック、または現在のプロジェクトタイプに一致 | 保持 |
| **時々必要** | ドメイン固有、CLAUDE.md で参照されていない | オンデマンド有効化を検討 |
| **ほぼ不要** | コマンド参照なし、コンテンツ重複、プロジェクトに明確に一致しない | 削除またはレイジーロード |

### フェーズ 3: 問題検出

以下の問題パターンを特定:

- **肥大化したエージェント記述** — フロントマターの description が 30 ワード超で、全 Task ツール呼び出しにロードされる
- **重いエージェント** — 200 行超のファイルは起動ごとに Task ツールコンテキストを膨張させる
- **冗長コンポーネント** — エージェントロジックを複製するスキル、CLAUDE.md を複製するルール
- **MCP 過剰サブスクリプション** — 10 サーバー超、または無料利用可能な CLI ツールをラップするサーバー
- **CLAUDE.md 肥大化** — 冗長な説明、古いセクション、ルールにすべき指示

### フェーズ 4: レポート

コンテキストバジェットレポートを生成:

```
コンテキストバジェットレポート
═══════════════════════════════════════

推定総オーバーヘッド: 〜XX,XXX トークン
コンテキストモデル: Claude Sonnet (200K ウィンドウ)
実効利用可能コンテキスト: 〜XXX,XXX トークン (XX%)

コンポーネント内訳:
┌─────────────────┬────────┬───────────┐
│ コンポーネント    │ 数     │ トークン   │
├─────────────────┼────────┼───────────┤
│ エージェント      │ N      │ 〜X,XXX   │
│ スキル           │ N      │ 〜X,XXX   │
│ ルール           │ N      │ 〜X,XXX   │
│ MCP ツール       │ N      │ 〜XX,XXX  │
│ CLAUDE.md       │ N      │ 〜X,XXX   │
└─────────────────┴────────┴───────────┘

⚠ 検出された問題 (N件):
[トークン削減量で順位付け]

上位3つの最適化:
1. [アクション] → 〜X,XXX トークン削減
2. [アクション] → 〜X,XXX トークン削減
3. [アクション] → 〜X,XXX トークン削減

削減可能量: 〜XX,XXX トークン（現在のオーバーヘッドの XX%）
```

詳細モードでは、ファイルごとのトークン数、最も重いファイルの行単位内訳、重複コンポーネント間の冗長行の特定、ツールごとのスキーマサイズ推定付き MCP ツールリストを追加出力。

## ベストプラクティス

- **トークン推定**: 散文は `単語数 × 1.3`、コード中心のファイルは `文字数 / 4`
- **MCP が最大のレバー**: 各ツールスキーマは約 500 トークン。30 ツールのサーバーは全スキルの合計よりコストがかかる
- **エージェント記述は常にロードされる**: エージェントが呼び出されなくても、description フィールドは全 Task ツールコンテキストに存在
- **詳細モードはデバッグ用**: オーバーヘッドの原因となる正確なファイルを特定する必要がある場合のみ使用。通常監査には不要
- **変更後に監査**: エージェント、スキル、MCP サーバーの追加後に実行してクリープを早期に検出
