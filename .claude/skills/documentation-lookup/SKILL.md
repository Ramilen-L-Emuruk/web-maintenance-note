# ドキュメント参照（Context7）

ユーザーがライブラリ・フレームワーク・API について質問した際は、学習データに頼らず Context7 MCP（`resolve-library-id` と `query-docs` ツール）を使って最新ドキュメントを取得して回答する。

## 主要概念

- **Context7**: ライブドキュメントを提供する MCP サーバー。ライブラリや API については学習データではなくこちらを使用する。
- **resolve-library-id**: ライブラリ名とクエリから Context7 互換のライブラリ ID（例: `/vercel/next.js`）を返す。
- **query-docs**: 指定したライブラリ ID と質問に対するドキュメントとコードスニペットを取得する。必ず先に `resolve-library-id` を呼び出して有効なライブラリ ID を取得すること。

## 発動タイミング

以下の場合に発動する:

- セットアップや設定に関する質問（例: 「Next.js ミドルウェアの設定方法は？」）
- ライブラリに依存するコードの要求（「Prisma で～のクエリを書いて」）
- API やリファレンス情報の要求（「Supabase の認証メソッドは？」）
- 特定のフレームワークやライブラリへの言及（React、Vue、Svelte、Express、Tailwind、Prisma、Supabase など）

ライブラリ・フレームワーク・API の正確かつ最新の動作に依存するリクエストに対して使用する。Context7 MCP が設定されているハーネス（Claude Code、Cursor、Codex など）全般で適用される。

## 使い方

### ステップ 1: ライブラリ ID の解決

**resolve-library-id** MCP ツールを以下のパラメータで呼び出す:

- **libraryName**: ユーザーの質問から抽出したライブラリ名またはプロダクト名（例: `Next.js`、`Prisma`、`Supabase`）。
- **query**: ユーザーの質問全文。結果の関連性ランキングが向上する。

`query-docs` を呼び出す前に、必ず Context7 互換ライブラリ ID（形式: `/org/project` または `/org/project/version`）を取得すること。有効なライブラリ ID なしに `query-docs` を呼び出してはならない。

### ステップ 2: 最適な候補の選択

解決結果から以下の基準で1件を選択する:

- **名前の一致**: ユーザーが求めているものと完全一致またはより近いものを優先。
- **ベンチマークスコア**: 高いスコアほどドキュメントの品質が高い（最高値は 100）。
- **ソースの信頼性**: High または Medium の信頼性を優先。
- **バージョン**: ユーザーがバージョンを指定した場合（例: 「React 19」「Next.js 15」）、バージョン固有のライブラリ ID（例: `/org/project/v1.2.0`）があればそちらを優先。

### ステップ 3: ドキュメントの取得

**query-docs** MCP ツールを以下のパラメータで呼び出す:

- **libraryId**: ステップ 2 で選択した Context7 ライブラリ ID（例: `/vercel/next.js`）。
- **query**: ユーザーの具体的な質問またはタスク。関連スニペットを取得するために具体的に記述する。

制限: 1 回の質問につき `query-docs`（および `resolve-library-id`）を 3 回以上呼び出さないこと。3 回呼び出しても回答が不明確な場合は、不確実性を明示した上で手元の最良情報を使用し、推測は避ける。

### ステップ 4: ドキュメントの活用

- 取得した最新情報を使ってユーザーの質問に回答する。
- 関連するコード例をドキュメントから引用して提示する。
- バージョンが重要な場合はライブラリ名またはバージョンを明記する（例: 「Next.js 15 では…」）。

## 使用例

### 例: Next.js ミドルウェア

1. **resolve-library-id** を `libraryName: "Next.js"`、`query: "Next.js ミドルウェアの設定方法"` で呼び出す。
2. 名前とベンチマークスコアで最適な候補（例: `/vercel/next.js`）を選択する。
3. **query-docs** を `libraryId: "/vercel/next.js"`、`query: "Next.js ミドルウェアの設定方法"` で呼び出す。
4. 返却されたスニペットとテキストで回答し、関連する `middleware.ts` の例があれば提示する。

### 例: Prisma クエリ

1. **resolve-library-id** を `libraryName: "Prisma"`、`query: "リレーション付きクエリの方法"` で呼び出す。
2. 公式 Prisma ライブラリ ID（例: `/prisma/prisma`）を選択する。
3. そのライブラリ ID とクエリで **query-docs** を呼び出す。
4. Prisma Client のパターン（例: `include` または `select`）とドキュメントからの短いコードスニペットを返す。

### 例: Supabase の認証メソッド

1. **resolve-library-id** を `libraryName: "Supabase"`、`query: "認証メソッドの種類"` で呼び出す。
2. Supabase ドキュメントのライブラリ ID を選択する。
3. **query-docs** を呼び出し、認証メソッドをまとめて取得したドキュメントから最小限の例を提示する。

## ベストプラクティス

- **具体的なクエリを使う**: 可能な限りユーザーの質問全文をクエリに使用し、関連性を高める。
- **バージョンを意識する**: ユーザーがバージョンを指定した場合、解決ステップでバージョン固有のライブラリ ID があればそれを使用する。
- **公式ソースを優先**: 複数の候補がある場合、コミュニティフォークより公式またはプライマリパッケージを優先する。
- **機密データを含めない**: Context7 に渡す前に、API キー・パスワード・トークン等のシークレットをクエリから取り除く。`resolve-library-id` や `query-docs` に渡すユーザーの質問に機密情報が含まれていないか確認する。
